## WPF Desktop: Hamburger Menu Folder Pane Toggle Fix

### 19. Fix Folder Pane Toggle — Replace Broken DoubleAnimation

**Problem:** Clicking the hamburger menu icon did nothing — the folder pane didn't collapse or expand.

**Root Causes (2 issues):**
1. **DoubleAnimation on GridLength**: `ColumnDefinition.WidthProperty` is `GridLength`, not `double`. The `DoubleAnimation` on `FolderPaneColumn` silently failed because WPF can't animate `GridLength` with `DoubleAnimation`.
2. **MinWidth="150"**: Even if the width was set to 0, `MinWidth="150"` on `FolderPaneColumn` prevented collapse below 150px.

**Fix:** Replaced broken animation with direct property setting:
- Set `FolderPaneColumn.MinWidth = 0` and `Width = new GridLength(0)` for collapse
- Set `FolderPaneBorder.Visibility = Collapsed` and `FolderPaneSplitter.Visibility = Collapsed`
- Restore to saved width on expand
- Removed unused `AnimateGridSplitter()` method

**File:** `applications/JubileeOutlook.wpf/JubileeOutlook/MainWindow.xaml.cs`

### 21. Fix Hand Cursor on Hamburger Menu — WindowChrome Override

**Problem:** The hamburger menu icon didn't show a hand/pointer cursor on hover, despite `Cursor="Hand"` in the style.

**Root Cause:** The window uses `WindowChrome` with `CaptionHeight="32"`, creating a 32px non-client title bar zone at the top. The hamburger button sits in this zone, so WindowChrome overrides the cursor to the default arrow (for window dragging). Other title bar elements already had `WindowChrome.IsHitTestVisibleInChrome="True"` but the `AppRailControl` was missing it.

**Fix:**

## Additional Technical Notes

- **setTimeout chain vs setInterval**: setTimeout chain prevents overlapping fetches — the next poll only starts after the previous one completes. Safer than setInterval which fires regardless of callback completion.
- **Cache-busting `_t` parameter**: `Date.now()` timestamp appended as query parameter forces the API to bypass any intermediate caching (CDN, browser, proxy).
- **Visibility/AppState listeners**: Ensure data is fresh when user returns to the app after switching tabs (web) or switching apps (mobile).
- **Migration 0007 idempotency**: Uses `ADD COLUMN IF NOT EXISTS` and `CREATE INDEX IF NOT EXISTS` — safe to run multiple times.
- **Table schema dual recurrence storage**: `recurrence_rule` (TEXT, from 0003) coexists with the 6 new dedicated columns (from 0007). The API uses the dedicated columns; `recurrence_rule` remains for potential future RFC 5545 RRULE string storage.
- **GridLength vs DoubleAnimation**: WPF `ColumnDefinition.Width` is `GridLength`, not `double`. `DoubleAnimation` silently fails — use direct property assignment instead.
- **WindowChrome cursor override**: Elements in the `CaptionHeight` zone of `WindowChrome` have their cursor overridden. Use `WindowChrome.IsHitTestVisibleInChrome="True"` to restore normal cursor behavior.
- **Dual event paths (Command + Click)**: When a WPF Button has both `Command` binding and `Click` handler, both fire on click. If both paths lead to the same method, it executes twice — use only one path.
- **Contact type namespace conflict**: `JubileeOutlook.ViewModels` namespace contains a `Contact` class (PeopleViewModel.cs) that shadows `JubileeOutlook.Models.Contact`. Use `Models.Contact` explicitly in ViewModel code.
