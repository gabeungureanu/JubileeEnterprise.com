## Technical Notes

- **Auth guard pattern**: `RequireUserId()` (WPF/C#) and `requireUserId()` (mobile/TS) both throw with the same message: "User is not authenticated. Please sign in to continue." This ensures API calls never silently use a null or fake user ID.
- **Dual method pattern**: `getUserId()` remains available for soft checks (auth state inspection, interceptors, UI guards), while `requireUserId()` is used for all service-layer API calls that must have a valid user.
- **Web frontend**: Already safe — no hardcoded test IDs, reasonable null guards in critical paths.
- **Contact validation**: All fields optional at API level. Frontend forms may enforce their own requirements (e.g., at least one phone number on mobile edit screen).
- **Restore flow**: PUT endpoint with `isDeleted: false` + ownership check with `includeDeleted: true` enables proper soft-delete restore.

## Calendar: 30-Second Auto-Refresh Sync (Web + Mobile)

### 11. Web CalendarPage — Auto-Sync with setTimeout Chain

Added 30-second background polling to keep calendar events in sync with the database.

**Changes:**
- Reduced cache TTL from 5 minutes to 30 seconds (`CACHE_TTL_MS = 30 * 1000`)
- Added `SYNC_INTERVAL_MS = 30_000` constant
- Implemented setTimeout chain polling pattern (prevents overlapping fetches vs setInterval)
- Added `visibilitychange` listener to refresh when user returns to tab
- Added `useRef` for `syncTimerRef` and `mountedRef` to manage cleanup

**Pattern:**
```typescript
const scheduleNext = () => {
  syncTimerRef.current = setTimeout(async () => {
    await fetchEvents(true);
    if (mountedRef.current) scheduleNext();
  }, SYNC_INTERVAL_MS);
};
```

**File:** `websites/inspire/jubileeoutlook.com/jubileeoutlook-frontend/src/pages/Calendar/CalendarPage.tsx`

## Data Layer: UserId Fragmentation Fix

### 15. Root Cause Analysis — Data Mismatch Across Platforms

Discovered data fragmentation across three different userIds for the same user (`logixasp@gmail.com`):

| UserId | Source | Platform |
|--------|--------|----------|
| `f66610b1-853e-41bd-a0b1-3d6670a68f36` | Real Codex userId (correct) | Desktop WPF |
| `187f1569-e0f3-49bc-8961-d62ea54f4985` | Synthetic SHA-256 hash of email | Web (email sync flow) |
| `00000000-0000-0000-0000-000000000001` | Default fallback | Desktop WPF (before auth) |

**Root Cause:** The web email sync flow in `SignIn.tsx` generated a synthetic UUID from `SHA-256(email)` instead of looking up the real Codex userId. All data created during sync-only mode was stored under a non-existent synthetic userId.

**Investigation:** Web showed "Test event" while desktop showed different data. Traced through all auth flows across 3 platforms (web, desktop WPF, mobile) to identify the fragmentation.

## Database: Calendar Event Creation Fix (Critical)

### 18. Migration 0007 Applied — Unblocked Event Creation

**Problem:** The `POST /api/v1/outlook/events` endpoint was failing with:
```

```

This blocked ALL event creation across all platforms (web, desktop, mobile).

**Root Cause:** Migration `0007_calendar_recurrence_fields.sql` existed in the repo but had never been applied to the database. The Continuum API's create and update event endpoints referenced columns that didn't exist.

| Column | Type | Purpose |
|--------|------|---------|
| `recurrence_type` | VARCHAR(20) | daily, weekly, monthly, yearly |

| `recurrence_end_date` | TIMESTAMPTZ | End date for recurrence |
| `recurrence_occurrences` | INTEGER | Max number of occurrences |
| `recurrence_days_of_week` | TEXT[] | Array of day names for weekly |
| `recurrence_exception_dates` | TEXT[] | Excluded dates from series |

**Index:** `idx_outlook_events_is_recurring` on `(user_id, is_recurring) WHERE is_recurring = TRUE`

**Verification:** Successfully created and deleted a test event via `POST /api/v1/outlook/events` after migration.

## Additional Technical Notes

- **setTimeout chain vs setInterval**: setTimeout chain prevents overlapping fetches — the next poll only starts after the previous one completes. Safer than setInterval which fires regardless of callback completion.
- **Cache-busting `_t` parameter**: `Date.now()` timestamp appended as query parameter forces the API to bypass any intermediate caching (CDN, browser, proxy).
- **Visibility/AppState listeners**: Ensure data is fresh when user returns to the app after switching tabs (web) or switching apps (mobile).
- **Migration 0007 idempotency**: Uses `ADD COLUMN IF NOT EXISTS` and `CREATE INDEX IF NOT EXISTS` — safe to run multiple times.
- **Table schema dual recurrence storage**: `recurrence_rule` (TEXT, from 0003) coexists with the 6 new dedicated columns (from 0007). The API uses the dedicated columns; `recurrence_rule` remains for potential future RFC 5545 RRULE string storage.
