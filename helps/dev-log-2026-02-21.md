## Codex API: Restore from Deleted Folder Fix

### 3. Ownership Check Includes Deleted Contacts

Fixed "Failed to restore contact" error when restoring from Deleted folder.

**Root Causes:**
- `verifyContactOwnership` excluded soft-deleted contacts (didn't pass `includeDeleted=true`)
- Validation skip condition `if (!body.isDeleted)` was incorrect for restore operations where `isDeleted=false`

**Fixes:**
- Changed PUT endpoint ownership check to `verifyContactOwnership(id, userId, true)`
- Simplified validation: always run, all fields optional — only format checks

**File:** `services/codex-api/src/index.ts`, `packages/database/src/codex.ts`

## WPF Application: Authentication Hardening

### 4. Remove Fake Test User ID Fallback

Removed all 14 occurrences of the hardcoded test user ID `00000000-0000-0000-0000-000000000001` across 5 WPF files. Added `RequireUserId()` method that throws `InvalidOperationException` with a clear message if the user is not authenticated.

**Pattern (before):**
```csharp
var userId = ServiceConfiguration.UserId ?? "00000000-0000-0000-0000-000000000001";
```

**Pattern (after):**
```csharp
var userId = ServiceConfiguration.RequireUserId();
// Throws: "User is not authenticated. Please sign in to continue."
```

## Technical Notes

- **Auth guard pattern**: `RequireUserId()` (WPF/C#) and `requireUserId()` (mobile/TS) both throw with the same message: "User is not authenticated. Please sign in to continue." This ensures API calls never silently use a null or fake user ID.
- **Dual method pattern**: `getUserId()` remains available for soft checks (auth state inspection, interceptors, UI guards), while `requireUserId()` is used for all service-layer API calls that must have a valid user.
- **Web frontend**: Already safe — no hardcoded test IDs, reasonable null guards in critical paths.
- **Contact validation**: All fields optional at API level. Frontend forms may enforce their own requirements (e.g., at least one phone number on mobile edit screen).
- **Restore flow**: PUT endpoint with `isDeleted: false` + ownership check with `includeDeleted: true` enables proper soft-delete restore.
