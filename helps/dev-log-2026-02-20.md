### 8. Quoted Header Format — Matches Web

Updated reply and forward quoted content to use the same header format as the web frontend.

**Reply (before):** `On [date], [name] wrote:` — no Subject field

## Mobile App: JubileeOutlookMobile (Mail Read State Persistence)

### 12. Read State Persistence Across Sync/Reload

Fixed mail read status not persisting across sync, soft reload, and hard reload.

**Root Causes:**
- `handleMessagePress` in MailScreen only did local optimistic update without calling `markAsRead` API
- MessageDetailScreen's markAsRead was fire-and-forget with silent error swallowing
- MailContext's `refreshMessages` did full replacement every 60s, overwriting local read state

**Fixes:**
- **MailScreen.tsx**: `handleMessagePress` now calls `markAsRead` API + optimistic folder count decrement + `loadFolders()` after success; focus handler refreshes folders; bulk mark-read refreshes folders
- **FolderMessagesScreen.tsx**: Added `markAsRead` API call in `handleMessagePress`; added focus handler with read-state merge logic
- **MessageDetailScreen.tsx**: Changed silent `.catch(() => {})` to logging `.catch((err) => console.warn(...))`
- **MailContext.tsx**: Changed `refreshMessages` from full replacement to merge pattern (preserves local read/pin state); `selectMessage` now does optimistic update + folder count decrement + refreshFolders after API

**Files:** `mobile/.../src/screens/mail/MailScreen.tsx`, `mobile/.../src/screens/mail/FolderMessagesScreen.tsx`, `mobile/.../src/screens/mail/MessageDetailScreen.tsx`, `mobile/.../src/context/MailContext.tsx`

---

### 13. Sidebar Unread Count Stability

Fixed sidebar unread count fluctuating after marking messages as read.

**Fix:** Optimistic decrement of `folder.unreadItemCount` immediately on message open, then reconcile with `loadFolders()` after backend confirmation. Both MailScreen and MailContext now refresh folder counts after read state changes.

**Files:** `mobile/.../src/screens/mail/MailScreen.tsx`, `mobile/.../src/context/MailContext.tsx`

## Technical Notes

- **Read state merge pattern**: `isRead: readIds.has(m.id) || m.isRead` — preserves local read state during refresh by OR-ing local state with API response. Applied in MailScreen, FolderMessagesScreen, and MailContext.
- **Optimistic folder count**: Decrement `unreadItemCount` locally on message open, reconcile with `loadFolders()` after API success.
- **Subject prefix convention**: Web uses `RE:` / `FW:`, mobile now aligned (was `Re:` / `Fwd:`).
- **Draft auto-save**: 30-second interval with string hash change detection. Silent failure — never interrupts user.
- **Signature injection**: Loaded from AsyncStorage via signatureService, inserted between user text and quoted content.
- **Importance cycling**: normal → high → low → normal, passed as `importance` field in sendMessage payload.
- **Mobile contacts architecture**: All API calls via `codexClient` (InspireCodex.com), DTO mapping with `mapContactDto()`, filter tabs and sort options driven by local state derived from API data.
- **WPF contacts architecture**: API-first via `ApiContactService` with offline-first sync support, event-driven ViewModel communication, gold-themed UI with hover/selection states.
