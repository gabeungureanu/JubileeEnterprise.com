## 1. Database Migration Endpoint (InspireContinuum)

### Problem
Database migrations needed to be executed on the production Continuum database, but the local migration tool couldn't connect directly.

### Solution
Added a secure migration API endpoint to InspireContinuum.

### Changes Made

**File: `websites/codex/InspireContinuum.com/server.js`**

Added two new endpoints:

1. `POST /api/v1/migrate` - Execute pending migrations
   - Requires `X-Migrate-Secret` header for authentication
   - Supports selective migration via `migration` parameter
   - Idempotent - checks for existing tables before running

2. `GET /api/v1/migrate/status` - Check migration status
   - Returns list of all tables
   - Shows which migrations are applied/pending

### Migrations Applied

**Continuum Database:**
- `0003_jubilee_outlook_schema.sql` - Created 14 new Outlook tables:
  - Calendar: `outlook_calendars`, `outlook_calendar_events`, `outlook_event_attendees`, `outlook_event_attachments`
  - Email: `outlook_email_folders`, `outlook_email_messages`, `outlook_email_recipients`, `outlook_email_attachments`
  - Contacts: `outlook_contacts`, `outlook_contact_emails`, `outlook_contact_phones`, `outlook_contact_addresses`, `outlook_contact_groups`, `outlook_contact_group_members`

**Extensions Enabled:**
- `uuid-ossp` - For UUID generation
- `citext` - For case-insensitive text

### Verification
```bash
curl https://inspirecontinuum.com/api/v1/migrate/status
# Returns: 23 total tables, 14 outlook tables
```

## 3. Check for Updates Feature Fix

### Problem
The "Check for Updates" button in the About Jubilee dialog was non-functional:
1. Button had no click handler attached
2. Update URL was incorrect (`www.jubileebrowser.com` vs `jubileebrowser.com`)
3. HttpClient URL path construction was broken (leading slash issue)
4. UI was static - didn't reflect actual update state

### Root Cause Analysis

**URL Construction Bug:**
```csharp
// BaseAddress: https://jubileebrowser.com/downloads (no trailing slash)
// Request: /{channel}/releases.json (with leading slash)
// Result: https://jubileebrowser.com/stable/releases.json (WRONG!)
// Expected: https://jubileebrowser.com/downloads/stable/releases.json
```

When HttpClient has a BaseAddress without trailing slash and the request path starts with `/`, it treats it as absolute from the host root.

### Solution

**File: `Services/UpdateManager.cs`**
```csharp
// Before
private const string UpdateEndpoint = "https://www.jubileebrowser.com/downloads";
var response = await _httpClient.GetAsync($"/{channel}/releases.json");

// After
private const string UpdateEndpoint = "https://jubileebrowser.com/downloads/";
var response = await _httpClient.GetAsync($"{channel}/releases.json");
```

## 4. In-Place DLL Update

### Process
For updating an existing 8.0.7 installation to 8.0.8 without reinstalling:

1. Close JubileeBrowser
2. Copy updated DLLs to `C:\Program Files\Jubilee Browser\`:
   - `JubileeBrowser.dll` (2.38 MB)
   - `JubileeBrowser.Shared.dll` (20 KB)
3. Restart JubileeBrowser

### Patch Files Location
```
applications/JubileeBrowser.wpf/JubileeBrowser.WPF/update-patch-8.0.8/
├── JubileeBrowser.dll
└── JubileeBrowser.Shared.dll
```

## Lessons Learned

1. **HttpClient URL Resolution**: Always use trailing slash on BaseAddress and avoid leading slash on relative paths
2. **WPF Event Handlers**: XAML buttons need explicit `Click` attributes - they don't inherit or auto-wire
3. **Database Migrations**: Creating API endpoints for migrations is safer than running scripts directly on production
4. **In-Place Updates**: .NET DLLs can be hot-swapped when the application is closed, enabling quick patches
