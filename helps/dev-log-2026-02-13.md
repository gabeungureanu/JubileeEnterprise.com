## 5. Inline Attachment Preview

### What
Images and PDFs can be previewed inline in a modal overlay directly from the reading pane. Non-previewable attachments download directly.

### Implementation
- `fetchAttachmentBlob()` added to mailService for fetching binary content
- `isPreviewable(mimeType)` helper checks against supported image types and PDF
- Modal overlay renders `<img>` for images, `<iframe>` for PDFs
- Blob URLs created on open, revoked on close to prevent memory leaks
- Previewable attachment cards show dashed blue border and visibility icon

### Supported Types
- Images: PNG, JPEG, JPG, GIF, WebP, SVG+XML, BMP
- Documents: PDF

## 6. Desktop Notifications for New Mail

### What
Browser desktop notifications fire when new unread emails arrive during auto-sync. Users can enable/disable from Settings > General.

### Implementation
- `notificationService.ts` wraps Browser Notifications API
- Permission requested on app mount
- `knownMessageIdsRef` (Set) tracks all seen message IDs, seeded on initial load
- During 60-second auto-sync, new unread messages not in the known set trigger notifications
- Notifications auto-close after 8 seconds, clicking focuses the window
- Enable/disable preference stored in localStorage (`jubilee_notifications_enabled`)

### Files Created/Modified
- `src/services/mail/notificationService.ts` (CREATED)
- `src/pages/Mail/MailPage.tsx` - notification detection in auto-sync, permission request
- `src/pages/Settings/SettingsPage.tsx` - notification toggle in General section

## 8. Email Rules/Filters

### What
Create rules with conditions and actions to automatically process incoming emails. Rules support multiple conditions with AND/OR matching and multiple actions.

### Implementation
- `rulesService.ts` provides localStorage-based CRUD
- Condition fields: from, to, subject, hasAttachment
- Condition operators: contains, equals, startsWith, endsWith, is
- Action types: moveToFolder, markAsRead, flag, delete
- Rules can be enabled/disabled individually
- Full CRUD UI in Settings > Rules tab with conditions/actions builders

### Types
```typescript
interface EmailRule {
  id: string;
  name: string;
  conditions: RuleCondition[];
  actions: RuleAction[];
  matchAll: boolean;  // AND vs OR
  enabled: boolean;
  createdAt: string;
  updatedAt: string;
}
```

## Technical Notes

- **No React Router**: JubileeOutlook uses `activeModule` state in AppContext with a switch in AppLayout to render pages. Module type: `'mail' | 'calendar' | 'people' | 'settings'`.

- **MailContext Pattern**: `MailContext.tsx` defines `MailContextValue` interface. `MailProvider` wraps the mail page. `useMailContext()` throws if outside provider; `useMailContextSafe()` returns null (used by Ribbon components rendered outside the provider).

- **localStorage Strategy**: Signatures, snooze data, rules, templates, notification preferences, and sync settings all use localStorage since no backend endpoints exist for these features yet. Keys are prefixed with `jubilee_` to avoid collisions.

- **contentEditable for Rich Text**: Signatures, templates, and compose body all use `contentEditable` divs instead of a third-party rich text library to keep the bundle small and avoid dependency complexity.

- **Auto-Sync Architecture**: MailPage runs a 60-second interval that calls `refreshMessages()`. Desktop notification detection hooks into this same interval by comparing message IDs against a `knownMessageIdsRef` Set. Snooze expiry checking runs on a separate 60-second interval.

- **Attachment Preview Memory Management**: Blob URLs created via `URL.createObjectURL()` are revoked on component unmount and when the preview closes to prevent memory leaks.
