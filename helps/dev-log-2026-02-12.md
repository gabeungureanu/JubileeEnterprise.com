## 1. Calendar Event Display Fix (CalendarViewModel.cs)

### Problem
Calendar events created in the app were not appearing on the calendar grid. Events were saved to the database successfully but the UI did not update.

### Root Cause
`Events.Add()` followed by `OnPropertyChanged(nameof(Events))` does not reliably trigger WPF `MultiBinding` converter re-evaluation. The `EventsByDateConverter` (which filters events per day column) only re-runs when WPF detects a property value change — but since the same `ObservableCollection` reference was returned, WPF skipped the converter.

### Fix
- Replaced manual `Events.Add()` + `OnPropertyChanged` with `UpdateVisibleEventsFromCache()` in all event creation/update/delete paths
- Modified `UpdateVisibleEventsFromCache()` to create a **new** `ObservableCollection` instance instead of clearing and re-adding items, guaranteeing a reference change that WPF detects
- Also force `OnPropertyChanged(nameof(VisibleDays))` to trigger the secondary MultiBinding input

### Files Modified
- `ViewModels/CalendarViewModel.cs`
  - `NewEventAsync()` - create path and error/offline path
  - `EditEventAsync()` - update, delete, and offline fallback paths
  - `UpdateVisibleEventsFromCache()` - new collection instance pattern

## 2. Timezone Conversion Fix (ApiCalendarService.cs)

### Problem
User creates event at 11:00 AM IST, but on reload it shows as 5:30 AM (shifted by -5:30 hours, the IST-to-UTC offset).

### Root Cause Chain
1. Database stores times correctly: `2026-02-12 11:00:00+05:30` (timestamptz)
2. node-postgres reads timestamptz and converts to JavaScript Date (always UTC internally): `2026-02-12T05:30:00.000Z`
3. Hono API serializes JS Date to JSON with Z suffix: `"startTime": "2026-02-12T05:30:00.000Z"`
4. .NET System.Text.Json deserializes "Z" suffix as `DateTimeKind.Utc`, value = 5:30 AM
5. `MapToCalendarEvent()` assigned UTC time directly without converting to local
6. `GetTimeRange()` and `LoadEventForEditing()` formatted UTC time as-is → displayed "5:30 AM"

### Fix (Two-sided)

**Loading (MapToCalendarEvent):**
```csharp
StartTime = dto.StartTime.Kind == DateTimeKind.Utc ? dto.StartTime.ToLocalTime() : dto.StartTime,
EndTime = dto.EndTime.Kind == DateTimeKind.Utc ? dto.EndTime.ToLocalTime() : dto.EndTime,
```

**Saving (MapToDto):**
```csharp
StartTime = calendarEvent.StartTime.Kind == DateTimeKind.Unspecified
    ? DateTime.SpecifyKind(calendarEvent.StartTime, DateTimeKind.Local).ToUniversalTime()
    : calendarEvent.StartTime.ToUniversalTime(),
```

### Files Modified
- `Services/ApiCalendarService.cs`
  - `MapToCalendarEvent()` (line 797-798) - UTC to local on load
  - `MapToDto()` (line 858-863) - local to UTC on save

## 3. Continuum API - Outlook Calendar Endpoints (index.ts)

### Problem
The Continuum API on port 4003 (TypeScript/Hono) had zero outlook/calendar routes. Events were getting 404 from the API. The routes only existed in the legacy Express server.js (port 3101, not running).

### Solution
Added 5 complete CRUD endpoints to `services/continuum-api/src/index.ts`:

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/v1/outlook/events` | List events with userId, date range, calendar filtering |
| GET | `/api/v1/outlook/events/:id` | Get single event with relations |
| POST | `/api/v1/outlook/events` | Create event with auto-default calendar |
| PUT | `/api/v1/outlook/events/:id` | Update event with COALESCE partial updates |
| DELETE | `/api/v1/outlook/events/:id` | Delete event |

### Key Implementation Details
- Uses `getContinuumPool()` for direct PostgreSQL access to `jubilee_continuum` database
- Helper functions: `mapEventRow()` (snake_case → camelCase), `fetchEventRelations()` (attendees, attachments, images)
- POST/PUT use transactions with explicit `BEGIN`/`COMMIT`/`ROLLBACK`
- POST auto-creates a default calendar if none exists for the user
- Supports both camelCase and snake_case property names in request bodies
- DELETE cascades to attendees, attachments, and images via database foreign keys

### Database Tables Used
- `outlook_calendar_events` (start_time/end_time are `timestamptz`)
- `outlook_calendars` (with `is_default` flag)
- `outlook_event_attendees`
- `outlook_event_attachments`
- `outlook_event_images`

## Technical Notes

- **WPF MultiBinding Gotcha**: `MultiBinding` converters only re-evaluate when the binding source's `PropertyChanged` event fires with a value that WPF considers "changed." For `ObservableCollection`, WPF checks reference equality — adding/removing items fires `CollectionChanged` but NOT `PropertyChanged`, so the converter never re-runs. The fix is to assign a new collection instance.

- **PostgreSQL timestamptz + node-postgres**: When reading `timestamptz` columns, node-postgres creates JavaScript `Date` objects that are always UTC internally. When serialized to JSON, they produce ISO 8601 strings with "Z" suffix. Any consumer must handle UTC-to-local conversion.

- **DateTime.SpecifyKind**: When .NET DateTime has `Kind == Unspecified`, calling `.ToUniversalTime()` assumes it's local time and converts. But `DateTime.SpecifyKind` is clearer about intent — explicitly marks the value as Local before converting to UTC.
